# 동행 시간 UTC 전환 배포 전 확인

동행 일정은 새 코드에서 UTC로 저장하고 장소 시간으로 응답한다. 이 변경은 기존 DB 값이 이미 UTC라는 전제 없이 운영에 적용할 수 없다.

기존 `companion_post.meeting_at`과 수동으로 확정한 `companion_schedule.scheduled_at`은 장소 현지 시각일 수 있다. NOW 자동 확정 일정은 UTC로 저장됐지만 이후 수정된 NOW 일정은 현지 시각일 수 있다. 일정 수정 이력이 남지 않아 값만으로 두 경우를 구별할 수 없다. V19와 V20 사이에 생성되거나 수정된 데이터도 적용 시점과 실제 기준을 확인해야 한다.

## 배포 전 작업

- 운영 DB에서 배포 버전과 Flyway V19·V20 적용 이력을 확인한다.
- 모집글·일정·장소·유형·매칭 상태를 함께 조회해 기존 값의 시간 기준을 검토한다. 기존 값을 자동으로 덮어쓰지 않는다.
- 확정할 수 없는 NOW 일정과 서머타임 전환 시각의 실제 약속을 확인한다. 시간대가 존재하지 않거나 두 번 발생하는 현지 시각은 하나의 UTC 시각으로 자동 결정하지 않는다.
- 실제 기준이 확인된 데이터에 한해 백업, 원본과 변환 결과 검증, 롤백 절차를 갖춘 별도 전환 작업을 준비한다.
- 앱이 입력 시각을 장소의 현지 시각으로 전송하고 응답을 별도 시간대 재변환 없이 표시하는지 확인한다.
- API와 데이터 전환 시점을 조율하고, 전환 중 새 쓰기가 발생하지 않도록 절차를 정한다.

이 확인이 끝나기 전에는 새 코드가 기존 현지 시각을 UTC로 오해할 수 있으므로 운영에 배포하지 않는다. 지원 도시를 찾지 못하는 새 입력과 응답은 UTC로 처리한다.
